# Analytics governance and interpretation limits

The current implementation is synthetic engineering validation only. No approved real
research dataset, completed independent pilot, approved gold split or production model
exists. Taxonomy approval is pending. No source permission is modified. Current APIs
reject real sources/rows and cannot promote synthetic fixtures into research data.
STEP 15 is not implemented.

Citizen feedback is a self-selected stream. Even future authorized data cannot directly
estimate satisfaction of all citizens, complaint incidence per service transaction or
causal agency quality. Missing service-exposure denominators, channel selection,
unobserved non-reporters, source coverage and annotation errors limit interpretation.
Agency/domain counts are observed volumes, not adjusted performance comparisons.

AI labels, human-reviewed workflow labels and adjudication labels are separate bases.
Current predictions and review actions are invented fixtures, not trained-model output
or actual independent annotators. The solo researcher context remains unchanged.
Unknown severity is explicit; missing reviews are not silently filled with model labels.
Review completion and correction shares are workflow measures, not accuracy estimates.
Three predictions and repeated events never multiply a feedback count. Correlated
cases/threads can still appear as separate feedback; analytics does not claim case-level
independence, inferential sampling or deduplication beyond existing source uniqueness.

Event timestamps must come from received_at. Missing dates remain missing; insertion
and inference times never stand in for real event dates. Reporting uses
Asia/Ho_Chi_Minh calendar boundaries with UTC storage. Complete calendar windows do not
prove complete data collection. Zero observed rows may reflect missing intake. Historical
synthetic alerts are retrospective for their displayed dates, not live monitoring.

Alert guards suppress small, undated, incomplete or unsupported comparisons. They do
not establish statistical significance, calibrated risk, crisis detection, false-positive
rate, seasonality control or incident verification. No automatic notification or
administrative action exists. New real thresholds require independent historical
validation and a documented research protocol, not tuning against a protected test set.

Default cell suppression k=5 protects direct small cells and within-partition residual
inference. It does not prevent repeated-query differencing, linkage with outside data
or reconstruction across filter combinations. It is not differential privacy or proof
of anonymity. All current rows are invented and real analytics stays blocked. A future
real deployment needs reviewed aggregation permissions, stronger query controls or
privacy budgeting, coarse dimensions and explicit disclosure review. No endpoint
returns raw text, actors or record identifiers. Even aggregate metadata needs access
control. Admin never overrides data usage rights.

Bounded metadata materialization defaults to 5,000 records and 366 days; overflow fails
instead of truncating. This is a local demo capacity ceiling, not a high-volume deployment
claim. A single request uses a consistent read snapshot; separate API calls may observe
different committed workflow states. PostgreSQL query/migration behavior remains
NOT_VERIFIED until dedicated local tests actually run. SQLite and Streamlit AppTest
cannot establish PostgreSQL integration, secure public deployment or scientific validity.

Before real analytics: obtain source/license and purpose rights, permission/retention
evidence, verified acquisition and STEP 04 privacy clearance, approved taxonomy and
annotation protocol, genuine pilot/adjudication/gold review, database integration and
privilege/backup validation, disclosure controls, domain-approved KPI definitions,
alert validation and deployment/security approval. Real model performance claims
additionally require the governed locked evaluation protocol. No current software status
substitutes for those human decisions.
